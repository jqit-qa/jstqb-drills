# jstqb-drills 更新契約

## ファイルの役割

| ファイル | 役割 |
|---|---|
| `index.html` | GitHub Pagesで公開する本番ドリル。依存なしの単一HTML |
| `JSTQB_FL_1-2章_4択問題バンク.md` | 全問題、選択肢、正答、解説のマスター |
| `JSTQB_FL_1-2章_確認ドリル.html` | 旧URLからルートURLへ送る互換リダイレクト |
| `tests/validate-drill.mjs` | 問題同期、保存・通知・UI契約の回帰テスト |
| `README.md` | 利用・保守・公開・通知の運用説明 |

## 問題データ契約

`index.html` の `QUESTIONS` は次の形式を使う。

```js
{id: 1, ch: 1, ref: "1.1.1", ans: 2, q: "問題文", opts: ["A", "B", "C", "D"]}
```

- `id`: 1〜50の一意な整数。保存データの識別子でもある
- `ch`: 章番号。現行は1または2
- `ref`: 公式シラバスの節番号
- `ans`: `opts` の0始まり正解index
- `q`: 4択で一意に答えられる問題文
- `opts`: A〜Dの固定表示順となる4選択肢

`SYLLABUS_PAGES` は `ref` ごとのPDF開始ページを保持する。PDFビューアの `#page=` と一致する実ページ番号を使い、紙面に印刷されたページ番号だけで判断しない。

## 現行の不変条件

- 合計50問
- 第1章25問、第2章25問
- 各問題4択
- シラバスページ、節番号、問題IDの順で出題
- 選択肢はシャッフルしない
- 正答位置はA=13、B=13、C=12、D=12を基準とし、各12〜13問に収める
- 実際の出題順で同じ正答位置を3問以上連続させない
- 初回50問完了後は誤答だけを再出題し、全50問正解まで繰り返す
- HTMLの問題・選択肢・正答とMarkdownの問題・解答表・解説を一致させる
- Slack通知は初回50問の完了通知であり、全問習得の証明ではない

## 保存形式の判断

| 変更 | `STORAGE_VERSION` / `STORAGE_KEY` |
|---|---|
| 問題文、選択肢、正答、問題ID、節、出題対象の変更 | 更新する |
| 問題の追加・削除・章ごとの抽出数変更 | 更新する |
| 保存JSONの構造変更 | 更新する。必要なら旧形式移行も実装する |
| PDF URL、ページ番号、画面説明、CSSだけの変更 | 通常は更新しない |

問題内容を変更したまま旧キーを使うと、旧版で習得済みの問題が新版でも習得済みとして復元される。互換性を優先せず、学習結果の正しさを優先する。

## 改訂影響表の判定基準

| 判定 | 基準 |
|---|---|
| 維持 | 新版でも問題文、正答、解説がそのまま成立する |
| 表現修正 | 意味と正答は同じだが、公式用語・表記に合わせる必要がある |
| 選択肢修正 | 誤答が新版では正しくなる、または現実的な誤解でなくなる |
| 正答変更 | 定義・原則・分類の変更で正答indexまたは正答内容が変わる |
| 差し替え | 学習目標から外れた、または新しい重要概念を優先すべき |

## 内容レビューのチェックリスト

- 学習目標の重要度に対して問題配分が偏っていない
- 定義問題だけでなく、理解・適用を問う問題を含む
- 「最も適切」「適切でない」の判定条件が明確
- 正答以外が条件次第で正しくならない
- 誤答は新人がしやすい混同、過度な一般化、役割の取り違えである
- 選択肢の長さや具体性だけで正答を推測できない
- 解説は正答理由と主な誤解を短く説明する
- 節番号とページリンクが新版に存在する
- 旧版固有の用語、版番号、URLが残っていない
