# JSTQB FLドリルを更新する

公式シラバスの変更を根拠に、問題・正答・解説・参照情報を同期更新する。推測で内容を補わず、変更根拠と影響範囲を追跡可能にする。

## 1. 更新権限と対象を確認する

1. リポジトリの `AGENTS.md` とプロジェクトメモリを読む。
2. Git状態、現在ブランチ、未コミット変更、既存PRを確認する。
3. 「比較・調査」の依頼ではファイルを変更しない。「更新」の依頼では最新 `main` から作業ブランチを作る。
4. `main` へ直接pushしない。変更を検証後、必ずPRを作る。マージ・Pages再設定・GASデプロイは明示的に依頼された場合だけ行う。
5. 第1章・第2章以外へ対象を広げる場合は、問題数、運用フロー、UIへの影響を先に確認する。

## 2. 公式資料を確定する

1. JSTQB公式サイトを検索し、一次情報から最新版のシラバス、リリース情報、正誤表を取得する。
2. 旧版と新版について、版番号、公開日、公式URLを記録する。検索結果や第三者の要約だけを根拠にしない。
3. PDFを扱う場合はPDF読取機能を使い、第1章・第2章、学習目標、用語、目次、ページ番号、改訂履歴を確認する。
4. 公式資料を取得できない、版番号が曖昧、正誤表との優先関係が不明な場合は更新を止め、確認事項として報告する。

## 3. 改訂影響表を作る

ファイル編集より先に、節単位で次を整理する。

| 新版の節 | 変更種別 | 変更内容 | 影響する問題ID | 対応 |
|---|---|---|---|---|
| 例: 1.2.3 | 用語変更 | 定義の表現を変更 | 3, 4, 5 | 問題文・解説を改訂 |

変更種別は少なくとも「章構成」「学習目標」「定義・用語」「概念・主張」「例示」「節番号」「ページ移動」「表記のみ」に分ける。ページ移動だけの変更と、正答に影響する意味変更を混同しない。

## 4. 問題を設計する

作業前に [references/project-contract.md](references/project-contract.md) を最後まで読む。

1. 既存50問を新版の学習目標と節へ再マッピングする。
2. 各問題を「維持」「表現修正」「選択肢修正」「正答変更」「差し替え」に分類する。
3. 新しい重要概念に問題がなく、削除された概念の問題が残る場合は、50問の総数を保ちながら差し替える。
4. 問題文と正答は公式資料に照らして一意に判定できるようにする。複数正解、条件不足、否定の重なりを避ける。
5. 誤答選択肢は新人が現実にしやすい誤解で構成する。冗談、メタ表現、明らかに不自然な選択肢を使わない。
6. シラバスを長く転載せず、内容を正確に言い換える。
7. 固定表示の正答位置から推測されないよう、A〜Dの分布と連続数を調整する。正答位置だけを変える場合も選択肢の意味と解説を再確認する。

## 5. 必須ファイルを同期する

同じコミットで次を更新する。

- `index.html`: `QUESTIONS`、`SYLLABUS_PAGES`、`SYLLABUS_VERSION`、`SYLLABUS_URL`、画面上の準拠表記
- `JSTQB_FL_1-2章_4択問題バンク.md`: 全問題、選択肢、解答表、解説、準拠版表記
- `README.md`: 準拠版、更新ルール、必要なら運用説明
- `tests/validate-drill.mjs`: 新しい不変条件や変更した保存形式の検証

旧URL互換用の `JSTQB_FL_1-2章_確認ドリル.html` はリダイレクト専用であり、問題データを置かない。

問題ID、問題文、選択肢、正答、節、出題対象を変更した場合は、旧進捗を誤って引き継がないよう `STORAGE_VERSION` と `STORAGE_KEY` を更新する。ページ番号、URL、説明文だけの変更では通常更新しない。判断理由をPRへ記載する。

## 6. 検証する

1. `node tests/validate-drill.mjs` を実行する。
2. `git diff --check` を実行する。
3. 旧版番号、旧URL、廃止用語、削除節が残っていないか `rg` で検索する。
4. 変更した全問題について、HTML、問題バンク、解答表、解説、改訂影響表の一致を目視確認する。
5. 50問、各章25問、各4択、正答位置A〜D各12〜13問、実際の出題順で同じ正答位置が3問連続しないことを確認する。仕様変更がある場合は、先に契約とテストを更新する。
6. ヒントリンクが新版PDFの正しいページと節を開くことを確認する。
7. 保存形式を更新した場合は、旧保存データの削除または移行、回答途中復元、誤答再挑戦を検証する。

## 7. PRで引き渡す

PR本文へ次を記載する。

- 旧版と新版の版番号・公式URL
- 改訂影響表の要約
- 維持・修正・差し替えた問題数と問題ID
- 正答位置の最終分布
- 保存形式を更新したか、その理由
- 実行した検証と結果
- 人による確認が必要な箇所

問題バンクとHTMLの片方だけを更新した状態で完了扱いにしない。公式資料に解釈の余地が残る場合は、該当問題を明示してレビューを求める。
